# Service Registry (v1.0)

This registry catalogs all core application-layer services, background processes, utility coordinators, and helper systems powering DukaanMitra (BazaarSync).

---

## 1. Core Operating System Services (`src/os-core/`)

### 1.1 MitraOS Engine Coordinator (`os-engine.ts`)
- **Purpose**: Boots the AI operating system loop. Binds background agents to state machines, instantiates the local thread event loops, and manages agent life cycles.
- **Dependencies**: `@google/genai`, Node.js Process limits.
- **Consumers**: Express app initialization (`server.ts`).
- **Status**: **Production Ready** (Fully simulated agent loop).

### 1.2 Command & Event Bus (`event-bus.ts`, `command-bus.ts`)
- **Purpose**: Coordinates in-memory publish-subscribe pathways. Receives business mutations (e.g. `StockAdjusted`, `CreditExtended`) and dispatches them to registered AI Agents or projection handlers.
- **Dependencies**: Custom TypeScript EventEmitter hooks.
- **Consumers**: REST route handlers, `WorkspaceOS`, Domain Agents.
- **Status**: **Production Ready**.

### 1.3 Policy Engine (`policy-engine.ts`)
- **Purpose**: Evaluates legal, credit limit, and risk policies prior to finalizing ledger mutations. Rejects operations violating compliance schemas.
- **Dependencies**: Static rule models.
- **Consumers**: `command-bus.ts`, REST API handlers.
- **Status**: **Advanced Prototype**.

### 1.4 Reasoning Store (`reasoning-store.ts`)
- **Purpose**: Captures and persists the intermediate thinking steps ("Chain-of-Thought") generated by Gemini models during compound business operations.
- **Dependencies**: Drizzle SQL schemas (`ai_cache` extensions).
- **Consumers**: `ai-agent` routing handlers, Admin Console.
- **Status**: **Production Ready**.

## 2. Artificial Intelligence Services

### 2.1 AI-Munim Parsing Engine (`server.ts` - `/api/munim/parse`)
- **Purpose**: Translates natural human speech inputs or text fragments into structured POS transactions.
- **Dependencies**: `@google/genai` (Gemini Flash), prompt engineering presets.
- **Consumers**: Quick-entry textboxes, `Omnibar.tsx`.
- **Status**: **Production Ready**.

### 2.2 OCR Scan & Extraction Service (`server.ts` - `/api/munim/scan-bill`)
- **Purpose**: Performs high-fidelity optical character recognition on scanned supplier invoices using multimodal models.
- **Dependencies**: `@google/genai` (Gemini Multimodal).
- **Consumers**: Purchase bill scanner drawers.
- **Status**: **Production Ready**.

### 2.3 AI Prompt & Response Cache (`server.ts` - `aiCache`)
- **Purpose**: Intercepts outgoing AI calls by calculating MD5 query hashes. Returns instantly on cache hits, reducing operational token costs to zero.
- **Dependencies**: Local SQLite/PostgreSQL caching records.
- **Consumers**: All `/api/munim/*` and `/api/ai/*` routes.
- **Status**: **Production Ready**.

---

## 3. Client Storage & Coordination Services

### 3.1 Offline Guest Synchronization Coordinator (`src/App.tsx`)
- **Purpose**: Directs fallback mock databases when user runs in local Guest Mode. Ensures zero-friction access.
- **Dependencies**: `localStorage`, Custom React state hooks.
- **Consumers**: Entire client POS, ledger, and stock tabs.
- **Status**: **Production Ready**.

### 3.2 Global Database Hydration Service (`server.ts` - `/api/db`)
- **Purpose**: Bundles all relevant user tables into a unified JSON cargo load on initial startup. Eliminates round-trips and ensures rapid interface load-times.
- **Dependencies**: Drizzle Query Builder.
- **Consumers**: React hydration hooks in `App.tsx`.
- **Status**: **Production Ready**.
